Build order — every step is something to click

  1. Kickoff on the leader (see §5). Repo cloned, DSH profile projectx exists, empty plugin loads, Captain answers "hello" in OpenBot.
  2. Issues. issue_* tools + markdown store. Captain opens PX-1 and it appears as a file.
  3. Inbox. inbox_post + approval_request. Captain can ask a question without burying it in chat.
  4. Screens. projectx-client takes the root slot: Home · Crew · Issues · Routines · Inbox. Served by dsh --profile projectx web behind Tailscale. From here Oscar uses the browser tab, not OpenBot.
  5. Grok Bot provider. bot_send hands an issue to FillLight Bot; result comes back; Captain is woken.
  6. First routine. Weekly X scout for ASO / Apple Ads / TikTok tactics → digest in Inbox. This is v1 done.

v1 routines for FillLight (after step 6)

  1. Weekly scout — X search for indie-dev ASO / Apple Ads / TikTok tactics; 1-page digest.
  2. Daily numbers — installs + revenue via Grok Bot connectors; flag drops; auto-open a "fix" issue.
  3. Creative pipeline — hooks → script → Postiz draft → approval → publish.
  4. Store watch — App Store Connect status, rejections, reviews → issues.

Not in v1

More than one product · OpenBot as a provider · Stripe · replacing DSH's sidebar for other sessions · mobile-specific UI (the web UI should just work on a phone).

5. Kickoff brief — for the agent on the leader

Oscar talks to a DSH agent on oscar-dev-server-leader through OpenBot. That agent reads this section and does the steps. Read-only first; ask before anything that installs, deletes, or costs money.

Facts you can rely on (checked 2026-11-04): user oscar; Ubuntu x86_64, 12 cores, 15 GB RAM; Node 22.23; git; dsh 0.2.1-rc.5 at /usr/bin/dsh with only the acp profile; no pnpm; OpenBot 0.60 as a systemd service, with one custom ACP agent "DSH CPA" → ~/.local/bin/dsh-cpa-acp → dsh --profile acp using provider cliproxyapi-dev-server; Tailscale serve already proxies / → 127.0.0.1:9119 (hermes) — do not change it. Also running: Capy, Hermes, T3, cloudflared, QuickBook360 dev. The Mac is not used for anything.
  1. Clone. git clone https://github.com/LieuGroup/ProjectX ~/src/ProjectX. Open docs/projectx.html (read it as text; it's the memory). Confirm the DSH version satisfies what we'll pin later.
  2. Install pnpm (ask first): npm i -g pnpm. Nothing else global.
  3. Profile. Create ~/.dsh/profiles/projectx from the web template: dsh projectx --from-default-profile web --dump-config > /dev/null (same trick dsh-superagent-prototype uses; verify the command with dsh --help first). Copy the cliproxyapi-dev-server model config from the acp profile's patch into it. Never print or commit the API key env value.
  4. Empty bundle. Create packages/projectx-profile with a package.json (dsh.bundle.patch) and a cordis.patch.yml that only sets the Captain's system prompt: "You are the Captain of ProjectX…" (use the words in §3). Model @deepseek-ai/dsh-experimental-agent-team-profile's layout. Install with dsh plugin --profile projectx add "link:$HOME/src/ProjectX/packages/projectx-profile".
  5. OpenBot agent. Add a second custom ACP agent in OpenBot named ProjectX Captain: a copy of dsh-cpa-acp that runs dsh --profile projectx instead of acp (the ACP server comes from dsh-base, so the profile must include it — check dsh --profile projectx --help). Oscar then talks to the Captain from his phone.
  6. Issues. Create issues/PX-1.md by hand ("Kickoff on the leader", status: done) so the format exists: YAML front-matter key, title, status, owner, product, created, blocked_by, then markdown body with Acceptance criteria. Then build the issue_* tools (build-order step 2) in packages/projectx-host.
  7. Commit often, push to LieuGroup/ProjectX, and update §6 of this file at the end of every session.
